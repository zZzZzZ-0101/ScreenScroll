# Decisions (append-only)

Format: `YYYY-MM-DD — decision — reason — alternatives considered`

- 2026-10-26 — Scroll-and-stitch via `captureVisibleTab`, not CDP — works on Chrome/Edge/Firefox with only `activeTab`; no debugger infobar — CDP `captureBeyondViewport` kept as an experimental M6 toggle.
- 2026-10-26 — DOM hints first, pixel analysis as fallback/validation — the extension owns the DOM, so it knows where text lines are; pixels cover canvas/iframes/images of text — pure pixel splitting (as in webtoon tools).
- 2026-10-26 — Globally optimal breaks via DP (Knuth–Plass style) — greedy breaking produces cascades of bad breaks — greedy (reference prototype).
- 2026-10-26 — Desktop only — user requirement — mobile PWA / Firefox Android dropped.
- 2026-10-26 — MIT licence; ideas only from AGPL OpenCapture — keep freedom to publish — AGPL.
- 2026-10-27 — TypeScript 5.9, not 7.0 — TS 7 (native port) was just released; typescript-eslint and WXT type generation are tested against 5.x — TS 7.
- 2026-10-27 — Build output stays at WXT's default `packages/extension/.output/chrome-mv3` (as CLAUDE.md says), not `dist/chrome-mv3` (TODO M0 wording) — avoids fighting WXT defaults; the two docs disagreed — custom outDir.
- 2026-10-27 — e2e uses a separate build (`wxt build --mode e2e` → `.output/chrome-mv3-e2e`) that adds `host_permissions` for localhost and a test hook guarded by the compile-time flag `__SP_E2E__` — Playwright can't click the toolbar button, so `activeTab` is never granted; production stays at zero host permissions (checked by the offline guard test) — granting `<all_urls>` in production.
- 2026-10-27 — Vite's modulepreload polyfill is disabled — it contains a `fetch()` call, which the offline guard forbids; extension pages load modules directly — allowlisting it.
- 2026-10-27 — Verified: `chrome.tabs.MAX_CAPTURE_VISIBLE_TAB_CALLS_PER_SECOND = 2` (from WXT's generated Chrome API types, which come from Chrome's API schema; developer.chrome.com was unreachable from the build sandbox). The ≥550 ms spacing in CAPTURE §9 is consistent with it. Still to confirm by experiment in M1 (quota error text + backoff).
- 2026-10-27 — Default hotkeys: Alt+Shift+P (full page), Alt+Shift+V (visible), Alt+Shift+O (open popup). Chrome allows at most 4 suggested keys per extension, so Select (S) and Element (E) get theirs in M4 when those modes exist — users can rebind at chrome://extensions/shortcuts.
- 2026-10-27 — Correction to the e2e permission entry above: the e2e build needs `<all_urls>`, not localhost host permissions. Verified by experiment: `captureVisibleTab` fails with "Either the '<all_urls>' or 'activeTab' permission is required" when only `http://localhost/*` is granted. Production is unchanged (no host permissions; enforced by the offline guard test).
- 2026-10-27 — The content script drives the capture loop and asks the service worker for each frame; the SW only paces `captureVisibleTab` and writes to IndexedDB — keeps the SW thin and restart-tolerant (each frame is one short request); the content script owns scroll state and the mutation log anyway — SW-driven loop.
- 2026-10-27 — Frames are stored uncropped (full viewport PNG + crop rect) and cropped at composition — no image decoding in the SW — cropping in the SW with OffscreenCanvas (costs SW time and memory).
- 2026-10-27 — PNG dimensions are read from the IHDR header, and data URLs are decoded with `atob`, so the SW never calls `fetch()` or decodes images — offline guard + thin SW.
- 2026-10-27 — Fixed elements are classified top/bottom by their top edge relative to mid-viewport — simple and matches the fixture cases; the spec's "mid-viewport overlay" class (modals) is left alone and will get its warning with `modal.html` — measuring anchoring from computed `top`/`bottom` values.
- 2026-10-27 — `data-src` is copied over `src` only when `src` is empty or a placeholder: tiny `data:` URIs, or a file name made only of placeholder words (`blank.gif`, `lazy-loading.svg`) — never replace a real image — matching any URL containing "lazy" (it matched `lazyriver-trip.jpg`).
- 2026-10-27 — Added a single global image wait (≤ 5 s) after the preload pass, on top of the per-frame 1.5 s wait from CAPTURE §5 — with slow images, a frame could be grabbed while an image across the seam was still loading (seen on `lazy-images.html`); plus a warning if any visible image is still incomplete at grab time — raising the per-frame timeout (slows every frame).
- 2026-10-27 — The preload pass stops at the capture's screen limit instead of a fixed 200 screens — on infinite pages it otherwise scrolled for up to 60 s through content capture would never reach.
- 2026-10-27 — `MutationLog` removes an empty `style=""` left on elements that had no `style` attribute before capture, in a final pass after all undos. Found by the Esc/error restore tests; doing it as an ordinary undo step was not enough (the attribute came back in some runs; exact CSSOM trigger not pinned down, possibly Chrome's `inset` shorthand). The final pass makes it order-independent.
- 2026-10-27 — Capture limits travel in the start message (default 300 screens / 200,000 px) so e2e tests can use a low cap; not exposed in the UI yet (Options page, M5).
- 2026-10-27 — `DomHints.forbidden` entries carry a `kind` (`line` | `atomic` | `image`) instead of being bare intervals — the content script can't know the page height T (it depends on paper settings chosen later), so the "image taller than 0.5·T → opaque" rule (CAPTURE §11) has to be applied at pagination time — content script deciding opaque images itself.
- 2026-10-27 — Opaque elements (canvas, iframes, embed/object) produce only `opaque` rects, not atomic forbidden intervals — pagination decides how to cut inside them (pixel gaps), which a forbidden interval would rule out; same-origin iframes are opaque too because their DOM is not walked — walking same-origin frames (later, if needed).
- 2026-10-27 — Text runs: a text node's text is spread over its line fragments in proportion to fragment width — CAPTURE §11 allows this; exact per-line text needs a Range per character — per-character ranges.
- 2026-10-27 — Fixed top headers are hidden *before* a frame settles. The freeze stylesheet's `transition-duration: 1ms` also applies to our own `visibility: hidden`, so the header still computed as visible when hints were read straight afterwards (seen in e2e: header text reported twice).
- 2026-10-27 — After injecting the freeze stylesheet, all running animations are finished with `document.getAnimations()` — the stylesheet doesn't affect transitions already in flight, so captures of the same page differed — `transition: none` (the spec keeps 1 ms so `transitionend` handlers still fire).
- 2026-10-27 — Scroll locks (overflow hidden on html/body) are undone only when no inner scroller was chosen and the document can't scroll — app shells like Gmail also lock html/body but scroll a panel; unlocking them could make the document the target — always unlocking.
- 2026-10-27 — Missing tab URL → "The browser blocks extensions on its own pages…" — without the `tabs` permission Chrome hides the URL of chrome:// and store pages, so they arrive with no URL; adding `tabs` just for a nicer message isn't worth the permission.
- 2026-10-27 — The service worker keeps only a cache of each capture's window id; the session record in IndexedDB holds tab and window ids, so a restarted worker carries on.
- 2026-10-27 — Started M2 with M1's manual real-site checks still open: they need the user's own browser, and the user said "continue" after being offered M2. M1 stays untagged until those checks are done.
- 2026-10-27 — Filename tokens: `{title} {domain} {url} {yyyy} {mm} {dd} {HH} {min} {HHmm}`; `{mm}` is the month (as in the default template), minutes are `{min}` — avoids the month/minute ambiguity in PDF_OUTPUT §7.
- 2026-10-27 — Fixed print scale is clamped to fit the printable width (with a flag for the UI) — content wider than the paper would otherwise be cut off at the right edge.
- 2026-10-27 — A row's "dominant colour" (PAGINATION §4) is the grey window of width 2τ+1 holding the most pixels, not the single most common value — with ±8 JPEG noise the most common value can sit at the noise edge and flag the other half of the noise as ink (caught by a unit test).
- 2026-10-27 — Pixel analysis uses luma grey — the spec allows grey or per-channel max; luma is cheaper and coloured text on a same-luma background is rare.
- 2026-10-27 — Pagination counts the forced-cut overlap inside T (a page with overlap is still ≤ T) — the page image must fit the printable box at scale s; TESTING's "≤ T + overlap" is the looser bound.
- 2026-10-27 — Opaque regions shorter than 0.9·T get +8 on their pixel cuts (keep a chart together if possible); taller ones are cut freely at pixel gaps. Images taller than 0.5·T count as opaque (CAPTURE §11).
- 2026-10-27 — Last-resort cuts: when no candidate sequence fits (no hints and no pixels, or pinned breaks further apart than a page), cuts every 8 px are added at badness 200 with overlap and the warning "no clean break was found" — the DP must always produce pages; never silently.
- 2026-10-27 — PageSlice.breakKind adds `manual` (user-pinned break) to the spec's union; pixel-derived candidates keep their graded kind (section/paragraph/tableRow/line) so the Studio colours them like DOM breaks.
- 2026-10-27 — Widow/orphan penalty (+6) applies to line-level cuts with fewer than 2 line boxes between the cut and the nearest block-level boundary on either side.
- 2026-10-27 — Rule-only rows (PAGINATION §4) require each off-mode column to be part of a vertical stroke at least 8 CSS px above and below the row; rows of a different colour (horizontal rules) neither extend nor break a stroke — the synthetic suite caught text descender stems (few columns, aligned across 3–4 rows) being taken for table rules, which let a cut land inside a line.
- 2026-10-27 — Pixel-only mode adds the penalties the DOM would otherwise give: cutting right under a line that starts a block (more space above it than below) costs +6 (orphan), or +40 when the line is ≥ 1.3× the typical line height (a heading) — the synthetic two-column fixture showed a heading separated from its text.
- 2026-10-27 — A pixel gap inside a ruled structure counts as a table-row break when it contains or borders a row of clearly different colour (a horizontal rule) — the rule row itself is often "ink" because the page margin beside the table differs from it.
- 2026-10-27 — PDF code is a separate entry point, `@scrollpress/core/pdf` — pdf-lib isn't tree-shakeable and was pulled into the service worker and content script (430 KB each) through the shared index.
- 2026-10-27 — Default footer drawn in M2 with Helvetica ("{domain} · {date}", "{page}/{pages}", 8 pt grey); non-WinAnsi characters show as "?" until M3's Unicode font support. The "⋯ continued" marker is a small "continued from previous page" note above the page content, outside the image.
- 2026-10-27 — `@napi-rs/canvas` pinned to pdf.js's 0.1.x line: two native copies (1.x for us, 0.1.x for pdf.js) in one process crashed with SIGSEGV.
- 2026-10-27 — Studio analysis and page composition run on the main thread with a yield between frames, not in a Web Worker (ARCHITECTURE "where possible") — simpler for v1 and fast on the fixtures; move to a worker if real long pages stall the UI.
- 2026-10-27 — Previews: the long strip and thumbnails come from the ≤ 320 px strip (ARCHITECTURE); the Pages view repaints each page from full-resolution frames when it scrolls into view, so it matches the export.
- 2026-10-27 — Long-image export composes parts up to 16,384 device px tall: the one place a canvas taller than a page is allocated, because the user asked for one long image (PDF_OUTPUT §6). Every other path stays at one page.
- 2026-10-27 — Print opens the generated PDF in a new tab (the browser's PDF viewer has the print dialog), as UI §2 of PRODUCT suggests ("open PDF → browser print").
- 2026-10-27 — The Studio opens after a cancelled or failed capture too, when frames exist, with a warning that it shows what was captured (UI §7 "Open what was captured").
- 2026-10-28 — Started M3 with M2's manual checks still open: the user asked to continue and will report on real-site testing later.
- 2026-10-28 — Verified (PDF_OUTPUT §2 "verify"): pdf-lib 1.17 exposes everything the glyphless text layer needs — `context.register/nextRef/assign/flateStream/obj`, `page.node.newFontDictionary`, `page.pushOperators` and the text operators including `Tz` via `PDFOperatorNames.SetTextHorizontalScaling`. Built a Type0/CIDFontType2 font with Identity-H, a ToUnicode CMap and a CIDToGIDMap. Checked by experiment: pdf.js and poppler (`pdftotext`, `pdffonts`) extract English and Chinese text in reading order; pdf.js reports every line at its rectangle (±0.5 pt); fontTools decodes and re-saves the font.
- 2026-10-28 — The glyphless TrueType (552 bytes) is generated in code (`core/pdf/glyphless.ts`), not copied from Tesseract or another project. Glyph 1 is a valid zero-contour outline: an empty `glyf` table made pdf.js warn that the table was missing, and stray padding made fontTools reject it.
- 2026-10-28 — CIDs are assigned 1, 2, 3… per distinct character (not Unicode code points), so characters outside the BMP (emoji, CJK extension B) work through UTF-16 surrogate pairs in ToUnicode. All CIDs map to the blank glyph 1.
- 2026-10-28 — Text layer ops are wrapped in q … Q: the text rendering mode is graphics state and leaked past ET, which made the footer drawn afterwards invisible (seen when rendering the page).
- 2026-10-28 — Text runs are sized so the font's ascent − descent (exactly 1 em) equals the line box height, and stretched with `Tz` to the measured width, so selection highlights cover the visible text. Each run goes to the page holding its vertical centre; the repeated overlap after a forced cut is skipped, so text is never found twice.
- 2026-10-28 — Header/footer text that Helvetica can't encode (e.g. Chinese titles) is drawn as a small image rendered by the browser with system fonts, plus an invisible text twin so it stays searchable — instead of bundling a Noto CJK subset (PDF_OUTPUT §4): no font files to ship (CJK fonts are megabytes) and every script the user's system can display works. Latin text stays real Helvetica text.
- 2026-10-28 — Links to anchors on the captured page become in-PDF jumps (/Dest to the page showing the target) when the target was captured; otherwise they stay URI links. Link rectangles crossing a page break get a clipped annotation on each page.
- 2026-10-28 — Bookmarks nest by level (an h3 goes under the nearest preceding h2/h1) and the PDF opens with the bookmarks panel (PageMode /UseOutlines).
- 2026-10-28 — Header/footer templates live in a pdf-lib-free core module (`core/templates.ts`) because the extension's settings code, shared with the service worker, needs their defaults; importing them from `@scrollpress/core/pdf` would have pulled pdf-lib back into the worker.
